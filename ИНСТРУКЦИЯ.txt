ИНСТРУКЦИЯ ПО УСТАНОВКЕ И ЗАПУСКУ ПАРСЕРА ВАКАНСИЙ HH.RU
===========================================================

1. ЧТО НУЖНО
------------
- ОС: Windows, Linux или macOS.
- Python 3.9 или новее (проверка: в терминале выполните `python --version`
  или `python3 --version`).
- Доступ в интернет к сайту hh.ru.
- Один сторонний модуль - requests (ставится одной командой, см. ниже).
  Весь остальной код использует только стандартную библиотеку Python.

2. УСТАНОВКА
------------
1) Положите в одну папку два файла:
      hh_parser.py        - сам парсер
      тз.txt              - исходное техзадание (для справки)
2) Откройте терминал (Windows: cmd или PowerShell; Linux/macOS: Terminal)
   и перейдите в эту папку, например:
      cd C:\Users\ВАШЕ_ИМЯ\парсер
3) Установите единственную зависимость:
      python -m pip install requests
   (если командой запуска Python служит python3 - везде используйте python3)

3. ЗАПУСК
---------
Базовый синтаксис:
      python hh_parser.py "ЗАПРОС1" "ЗАПРОС2" ...

Примеры:
      python hh_parser.py "C#"
      python hh_parser.py "C#" "база данных" "Frontend"
      python hh_parser.py "база данных" --pages 10 --limit 50 --delay 0.5

Дополнительные параметры:
      --pages  N   - сколько страниц выдачи просканировать, максимум 20
                     (по умолчанию 20);
      --limit  N   - сколько вакансий (максимум) открыть для сбора
                     ключевых навыков (по умолчанию 200);
      --delay  N   - пауза между запросами к hh.ru в секундах
                     (по умолчанию 0.8; ставьте больше, если ловите капчу);
      --captcha-wait N - сколько секунд ждать, если hh.ru показал капчу
                     (по умолчанию 45; скрипт сам делает паузу и повторяет
                     запрос);
      --out    П   - папка для результатов (по умолчанию results).

Один запрос обрабатывается приблизительно за 3-7 минут
(зависит от количества страниц и вакансий, а также от пауз при капче).
Идите за прогрессом в консоли.

4. РЕЗУЛЬТАТЫ
-------------
Для каждого запроса создаётся своя папка внутри results/:

      results/c_sharp/          <- запрос "C#"
      results/база_данных/       <- запрос "база данных"
      results/frontend/          <- запрос "Frontend"

Внутри каждой папки 4 файла (JSON в кодировке UTF-8):

  vacancies.json        - отобранные вакансии с поисковых страниц, формат:
                          { "id", "name", "url", "employer", "area", "salary" }

  skipped.json          - вакансии, отброшенные как нерелевантные запросу
                          (например, "Сотрудник склада" на запрос
                          "база данных"), с причиной отбраковки.
                          Файл нужен, чтобы проверить, что лишних вакансий
                          в выборку не попало.

  vacancies_skills.json - те же вакансии (не более 200), но с собранными
                          ключевыми навыками:
                          { "id", "name", "url", "employer", "area",
                            "salary", "skills": ["SQL", "Docker", ...] }

  stats.json            - статистика по навыкам:
                          {
                            "query": "C#",
                            "vacancies_total": 198,        // собрано со страниц выдачи
                            "vacancies_parsed": 150,       // после фильтра релевантности
                            "vacancies_with_skills": 141,  // у которых нашлись навыки
                            "distinct_skills": 240,        // сколько разных навыков
                            "skills": [ { "skill": "C#", "count": 120,
                                          "share": 85.1 }, ... ]
                          }
                          share - доля вакансий с этим навыком от
                          vacancies_with_skills, в процентах.

Консольный итог печитается в конце запуска (сводка и топ-5 навыков),
лог всего прогона сохраняется в results/run.log.

5. КАК ПРОВЕРИТЬ КАЧЕСТВО ОТБОРА
--------------------------------
Откройте results/<запрос>/skipped.json: там должны быть названия вида
"Сотрудник склада", "Грузчик", "Менеджер по продажам" и т.п. - они
отброшены, потому что в названии вакансии нет слов запроса.
Проверить обратное можно в vacancies.json: там только вакансии, в названии
которых есть все слова запроса (с учетом основы слова и синонимов:
"C#" -> c#, "Frontend" -> front-end/фронтенд, "база данных" -> "баз" + "данн").

6. ЕСЛИ ЧТО-ТО ИДЁТ НЕ ТАК
--------------------------
- "Не установлен модуль requests":
      python -m pip install requests
- "hh.ru показал капчу/проверку":
      скрипт сам выжидает паузу (--captcha-wait, по умолчанию 45 c) и
      повторяет запрос. Если капча ловится постоянно - сделайте паузу на
      несколько минут и перезапустите с большим параметром:
      python hh_parser.py "C#" --delay 2
- Ошибка "HTTP 429" / медленная работа:
      уменьшите частоту:  --delay 1.0  и/или  --pages 5
- Пустые результаты:
      запрос слишком редкий - попробуйте другую формулировку
      в кавычках, например "database" вместо "база данных".
- Кодировка в консоли Windows (кракозябры):
      выполните перед запуском  chcp 65001
      (в PowerShell:  [Console]::OutputEncoding = [Text.Encoding]::UTF8)

7. ВАЖНО
--------
Сайт hh.ru может менять вёрстку. Если парсер вдруг начнёт собирать
пустые списки - обновите селекторы (атрибуты data-qa вида
"vacancy-serp__vacancy", "serp-item__title-text", "skills-element")
под текущую разметку страницы.
Соблюдайте паузу между запросами: не злоупотребляйте нагрузкой на сайт.
